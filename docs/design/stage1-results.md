## 1. 결정: Taichi 유지 (Warp로 전환하지 않음)

| 확인 항목 | 결과 |
|---|---|
| CUDA 백엔드 | `ti.cuda`로 RTX 4050 동작 확인 |
| f32·f64 원자 연산 | 동작함 |
| 단일 주소 원자 연산 | 셀마다 같은 주소에 더하면 심각하게 직렬화된다(chemistry 1.15ms → 0.1ms 차이). 열 단위 부분합(`col_sink[·, x]`) 후 합산하는 패턴으로 해결했다 |

결론: 차단 이슈가 없으므로 Taichi를 유지한다. Warp 전환은 단계 2에서 S2(5만 마리 ≥ 200 tick/s)를 달성하지 못할 때만 다시 검토한다.

## 2. 결정: 화학장 정밀도 f64

- f32에서는 정상상태 칸의 반올림 오차가 매 tick 같은 방향으로 반복된다. 그 결과 전자 수지 오차가 **시간에 비례해** 커졌다.
  - 측정값: 1만 tick 9.9e-6 → 10만 tick 2.4e-4.
  - 이 추세라면 100만 tick에서 0.1%를 넘는다.
- `chem`, `delta`, 열 부분합을 f64로 바꿨다.
- 비용: GPU 시간이 0.68 → 약 1.3ms/tick(경합 없는 추정)으로 늘었다. 원인은 메모리 대역폭이다.
  - f32 플럭스 계산 + f64 누적 방식도 시험했지만 이득이 없어서 되돌렸다.

## 3. 단계 1에서 조정한 파라미터

| 파라미터 | 이전 → 현재 | 이유 |
|---|---|---|
| `k_den` | 2e-4 → 1e-6 | 바다 N이 5만 tick 안에 1/300로 붕괴했다. 평형 N ≈ 열수구 N 공급 / k_den ≈ 셀당 0.3이 되도록 맞췄다 |
| `k_bury_r` | 2e-4 → 2e-3 | R 매몰(0.3/tick)이 열수구 공급(2/tick)보다 작아서 R이 계속 증가했다 |
| `k_weather` | 2e-6 → 1e-5 | 풍화(0.17/tick)가 열수구 CO₂(0.8/tick)를 상쇄하지 못했다. 현재 값의 평형은 pCO₂ ≈ 1.4, 수면 약 7°C, 결빙 없음이다 |

## 4. 기후 계수 허용 범위 (설계 §2.5-2 요구사항)

- 결빙 피드백 이득은 c/w다.
  - c/w > 1이면 부분 결빙 상태가 불안정해지고 쌍안정(히스테리시스)이 생긴다.
  - 현재 값은 c = 15, w = 5로 이득이 3이다.
- 히스테리시스 창의 폭은 ln p 기준으로 (c − w)/a_co2 = 1.67이다.
  - 태양 0.75에서 결빙은 pCO₂ < 0.435에서 시작되고, 해빙은 pCO₂ > 2.30이 되어야 일어난다.
  - 해빙에 필요한 CO₂는 화산이나 열수구에서 공급될 수 있으므로 **눈덩이 지구는 탈출 가능**하다(테스트로 확인).
- 권장 범위
  - 1.5 ≤ c/w ≤ 5. 5를 넘으면 창이 너무 넓어져 탈출에 수억 tick이 걸릴 수 있다.
  - a_ch4 ≤ 10. 대기 CH₄ = m_ref일 때 +a_ch4 °C이고, 이 범위면 CH₄ 단독으로 CO₂ 효과를 압도하지 않는다.
- `√M`의 단위: M은 대기 CH₄ 양을 `m_ref`(1e4)로 나눈 무차원 값이다.

## 5. 수지 오차 정의 (S6 보완)

- C와 N은 설계대로 `|실제 − 기대| / 현재 총량`이다.
- 전자(e)는 산화제(O₂)가 쌓이면 총량 E가 0을 지나갈 수 있다. 그래서 분모를 **기여 절댓값의 합 Σ|e_i·양_i|**로 둔다.
  - 0 근처에서 분모가 폭발해 의미 없는 상대오차가 나오는 것을 막기 위해서다.

## 6. 설계 대비 차이와 이월 항목

- `B_org`, `B_carb`: 관찰용 누적 슬롯(`acc[BUR_ORG]`, `acc[BUR_CARB]`)을 수지 싱크와 별도로 둔다.
- 다음 항목은 **단계 6으로 이월**한다(설계의 단계 표와 같다). 그전까지 결빙 탈출에 필요한 CO₂는 열수구가 공급한다.
  - 화산(포아송)
  - 태양 광도 증가
- 온도와 빛은 렌더링과 이후 생물용으로 매 tick 장(field)에 계산해 둔다(설계상 "저장 안 함"에서 바꿈, 3MB).
