## 1. 구현 범위

| 항목 | 구현 |
|---|---|
| 개체 풀 | 고정 131,072 슬롯, `state`(DEAD/ALIVE/DYING), 원자 free-list. 사망은 push 전용 커널(`die`), 출생은 pop 전용 커널(`reproduce`)로 분리했다. 풀이 비면 `atomic_sub` 결과를 되돌리고 분열을 실패 처리한다 |
| 참조 | 슬롯은 이동하지 않는다. `uid`는 64비트이고 재사용하지 않는다. 부모 `uid`를 저장한다 |
| 대사 | 수소 화학합성(2H + C + N → 몸), 무산소 호흡(몸 + 2X → C + 2R), 메탄 생성(2몸 → C + M) |
| 에너지 | ΔG 규칙. 수율 `−ΔG × η`이고 ΔG는 `reactions.py`의 μ 표에서 계산한다. 유지 비용 = (기본 + 형질 비용 × Ση) × 몸. 저장량이 예비분(20%) 아래로 떨어지면 몸을 태워 호흡한다 |
| 자원 경쟁 | 같은 칸의 개체들은 원자 `take`(뺀 뒤 모자란 만큼 되돌림)로 물질을 가져간다. 각 개체는 남은 양까지만 가져가므로 물질 중복이나 손실은 없다. 단, 빼고 되돌릴 때의 f64 반올림으로 약 −1e-18 수준의 음수가 남을 수 있다(CUDA 검사 기준 ≥ −1e-15) |
| 성장·분열 | 몸 ≥ `div_size` 유전자이고 에너지 ≥ 상한의 10%이면 분열한다. 몸과 에너지를 정확히 반분한다. 이 문턱은 예비분(20%)보다 낮다. 그래서 몸을 태우는 중에도 분열할 수 있고, 딸세포는 예비분 아래에서 시작할 수 있다. 에너지를 만들어내지는 않는다(반분 + 상한 절삭은 에너지를 줄이기만 한다) |
| 돌연변이 | 유전자마다 가우시안(σ = `mut_rate` 유전자 × 유전자 범위)을 더하고 범위로 클램프한다. 1% 확률로 유전자 하나를 균일 재추첨한다 |
| 사망 | 에너지 < 0, 몸 ≤ 최소, 또는 배경 사망률 2e-4/tick. 몸은 그 칸의 D(사체)가 되고, 이후 분해·매몰은 단계 1 화학이 처리한다 |
| 이동 | 해류(유선 함수)에 따른 수동 표류 + 랜덤 워크. 능동 이동은 단계 3에서 추가한다 |
| 수지 | 몸 탄소(f64)를 C·N(몸/6.6)·e(4×몸) 총량에 포함한다 |
| 뷰어 | 개체를 체색 점으로 표시하고, 개체 수·바이오매스·평균 유전자를 보여준다 |

유전체는 형질 10개다. 설계의 128(형질 24 + 뇌 104)은 형질·뇌가 열리는 단계 3에서 확장한다. 공간 해시도 개체 간 상호작용(포식·감각)이 생기는 단계 3으로 미룬다. **그래서 S2 성능은 단계 3에서 다시 측정해야 한다.**

## 2. 조정한 파라미터

| 파라미터 | 이전 → 현재 | 이유 |
|---|---|---|
| `divide_energy_frac` | 0.5 → 0.1 | 성장할 때 몸이 늘면서 에너지/몸 비율이 약 0.17로 희석된다. 그래서 0.5에 도달하지 못해 분열 없이 몸만 커지다(최대 6.9) 전멸했다. 관찰된 에너지/몸 비율(0.17~0.45)보다 낮은 값으로 정했다 |
| η 유전자 상한 | 1.0 → 0.95 | 설계 §2.3의 η < 1을 유전자 범위로 강제한다. 1.0이면 단계 4에서 역반응 쌍이 생겼을 때 사이클 순에너지가 0이 된다 |

**판정: S4 통과 (10개 중 9개 존속, 기준 ≥ 8).** S6도 전 구간에서 최대 3.8e-11로 통과했다.

해석은 다음과 같다.
- seed 5는 창시 직후(2천 tick)에 멸종했다. 원인은 **추정**이다: H₂가 0에서 시작하는 초기 바다에서 창시 집단이 열수구 근처에 자리 잡기 전에 굶었을 가능성이 있다(원인 분석은 하지 않음). 기준 안의 결과라서 튜닝하지 않는다.
- seed 2는 개체 8마리까지 줄었다가 회복했다(병목). 회복한 집단의 t_opt는 3.3°C로, 열수구에서 떨어진 차가운 물에 적응한 계통이다.
- 모든 생존 세계에서 η_H2가 약 0.98로 수렴했다.
- 나머지 형질(t_opt 3~58°C, η_메탄, η_무산소)은 세계마다 다르게 갈라졌다. 같은 규칙에서 **세계마다 서로 다른 진화 경로**가 나온 것이다.

## 5. S2 성능 판정 (GPU 경합 상태)

- 외부 Python 3.14 프로세스가 GPU를 간헐적으로 점유한다. 사용자 확인 결과 이 프로세스는 멈출 수 없다.
- 그래서 사용자 지시에 따라 **경합 상태의 측정값으로 판정**한다.
- 측정 방법: 개체 수를 정확히 5만으로 고정했다(`life.capacity=50000`, `vent_h=2.0`). 측정 구간 1000 tick 동안 풀이 가득 찬 상태다.

| 측정 | 값 | 비고 |
|---|---|---|
| GPU 커널 시간 합(평균), 경합 상태 | 4.55 ms/tick → **약 220 tick/s** | 판정에 쓴 값. 목표 200을 근소하게 넘는다 |
| GPU 커널 시간 합(최소) | 1.44 ms/tick → 약 690 tick/s | 경합이 없을 때의 상한 추정 |
| 벽시계, 고정 5만 마리 | 32 ~ 114 tick/s (5회) | 외부 프로세스의 GPU 시간 분할 때문이다. 예: `gas_exchange`는 평소 0.004 ms인데 최대 123 ms까지 튄다 |
| 벽시계, 고정하지 않음(4.7만~8.7만 마리) | 202 ~ 455 tick/s | 측정 시점의 경합 정도에 따라 크게 흔들린다 |

**판정: 통과 (근소).** 이 코드가 tick마다 쓰는 GPU 시간은 경합 상태에서도 목표 안에 든다. 벽시계 처리량은 외부 부하가 지배하므로 판정에 쓰지 않는다.

남은 위험
- 여유가 10% 정도뿐이다. 단계 3에서 뇌·공간 해시·포식이 추가되면 넘을 가능성이 높다.
- 지금 비용의 약 70%는 단계 1의 f64 환경 커널(수송 2개 + 화학)이다. 단계 3에서 가장 먼저 줄일 후보는 수송 적용 패스를 화학 커널에 합치는 것(약 0.4 ms 절감)이다.
