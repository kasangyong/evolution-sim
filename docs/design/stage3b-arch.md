## 결정 1. 개체 간 만남 (공간 구조)

포식에는 "같은 곳에 있는 다른 개체 하나"가 필요하다. 감각 입력(주변 밀도, 크기 차)에는 칸 단위 합계만 있으면 된다.

| 옵션 | 설명 | trade-off |
|---|---|---|
| A. 카운팅 정렬 공간 해시 (설계 rev 5) | 칸별 개수 → prefix-sum(`PrefixSumExecutor`) → 산포. 칸 안의 모든 개체를 나열할 수 있다 | 범용이다. 하지만 CUDA 전용 prefix-sum이라 CPU 테스트 경로를 따로 만들어야 하고, 칸 39만 개를 매 tick 스캔한다 |
| **B. 칸별 만남 후보표 + 칸 합계장** | 매 tick 각 개체가 확률 p로 자기 칸의 후보 슬롯에 자기 번호를 쓴다(마지막에 쓴 개체가 남는다). 포식자는 자기 칸 후보를 만남 상대로 읽는다. 감각용 칸 합계(개체 수, 바이오매스, 평균 크기)는 단계 3a의 `cell_body`처럼 원자 합으로 만든다 | 정렬이 없어서 가장 싸고, CPU·CUDA 코드가 같다. 만남이 칸당 tick마다 1건으로 제한된다. 대신 실제 플랑크톤의 "확률적 조우"와 성격이 같다 |
| C. 정렬 없이 이웃 슬롯 무작위 탐색 | 무작위 슬롯을 뽑아 같은 칸인지 확인 | 개체가 드문 곳에서 거의 실패한다 |

**추천: B.** 설계 rev 5와 다르므로 결과 문서의 "설계 대비 차이"에 적는다.
- (1차 평가 M1 후 수정) 처음 구현한 "확률 0.5로 쓰고 마지막 쓰기가 남는다"는 슬롯 단위라서 세포 1만 개 묶음과 세포 1개 슬롯이 같은 빈도로 만났고, CPU에서는 번호가 큰 슬롯으로 치우쳤다. 지금은 가중 저장소 표본추출(Efraimidis–Spirakis)이다. 각 슬롯이 `−ln(u) / ncell`을 양자화해 슬롯 번호와 묶은 키를 만들고, 칸마다 `atomic_min`으로 가장 작은 키를 고른다. 선택 확률이 세포 수에 비례하고 슬롯 순서와 무관하다. CPU·CUDA 코드가 같다.

**예상 리스크**
- 칸 하나에 후보가 하나뿐이라 포식자가 많은 칸에서는 같은 먹이를 여럿이 노린다.
  - 완화: 먹이 몸에서 빼는 것은 원자 `take`와 같은 방식(빼고 모자라면 되돌림)으로 한다. 물질이 복제되지 않는다.

## 결정 2. 포식

| 옵션 | 설명 | trade-off |
|---|---|---|
| A. 통째 삼키기 | 먹이 개체 전체를 사망 처리하고 몸을 가져온다 | 직관적이다. 슈퍼개체(세포 n개 묶음)에서는 묶음 전체가 한 번에 사라져 부자연스럽다 |
| **B. 한 입씩 (grazing)** | 포식자 몸에 비례한 양 `k_pred × η_pred × 몸`을 먹이 몸에서 원자적으로 뺀다. 동화 효율 ε만큼 포식자 몸이 되고, 나머지(1 − ε)는 그 칸의 사체 D가 된다. 먹이 묶음의 세포 수 n도 같은 비율로 준다 | 슈퍼개체와 맞는다. 물질 흐름이 몸 → 몸 + 사체뿐이라 C·N·전자 수지가 자동으로 맞는다(몸과 사체의 e·μ가 같다) |

**추천: B.**
- 먹이 조건: 포식자의 세포 크기(몸/n)가 먹이 세포 크기보다 커야 한다. 크기 비율 문턱은 유전자로 둔다.
- 에너지는 바로 생기지 않는다. 포식자는 늘어난 몸을 기존 호흡 경로로 태워서 에너지를 얻는다. 그래서 포식에도 산화제(O₂ 또는 X)가 필요하고, 호기 호흡과 결합할 때 수율이 가장 크다. 실제 생태와 같다.
- ε는 0.6으로 둔다(**추정치**. 원생생물 섭식 효율 문헌값 0.3~0.7의 중간). 1 미만이므로 포식 사슬에서 물질이 사체로 새어 나간다.
- 포식 유전자에도 유지비를 붙인다.

## 결정 3. 뇌와 행동

설계 결정 3: 입력 8 → 은닉 8 → 출력 4, 유전체 24–127(104개 가중치).

| 입력 | 값 |
|---|---|
| 빛 | 칸 빛 |
| R | 칸 R / (R + k_half) |
| O | 칸 O / (O + k_half) |
| 온도 | (칸 온도 − 최적 온도) / 폭 |
| 주변 밀도 | 칸 개체 수의 로그 |
| 크기 차 | 칸 평균 세포 크기 대비 내 세포 크기의 로그 비 |
| 내 에너지 | 에너지 / (상한 × 몸) |
| 바닥 거리 | (바닥 깊이 − y) / 수심 |

| 출력 | 행동 |
|---|---|
| 이동 x, 이동 y | tanh × 이동 속도 유전자(칸/tick)만큼 능동 이동을 더한다 |
| 섭식 모드 | > 0이면 이번 tick에 포식을 시도한다 |
| 분열 억제 | > 0이면 분열 조건을 채워도 분열하지 않는다 |

| 옵션 | 설명 | trade-off |
|---|---|---|
| **A. 고정 구조 8-8-4, tanh, 가중치 = 유전자** | 설계 그대로. 은닉 편향 8개 포함 64 + 8 + 32 = 104 | 단순하고 GPU 친화적이다 |
| B. 출력 편향 추가(108) | | 행동 기본값을 쉽게 진화시킨다. 유전체 128을 넘는다 |

**추천: A.** 창시자의 뇌 가중치는 0이다. 출력이 0이므로 이동하지 않고, 포식하지 않고, 분열을 억제하지 않는다. 단계 3a와 행동이 같다.

- 이동 비용: `k_move × 속도² × 몸`을 매 tick 에너지에서 뺀다. 수동 표류(해류 + 랜덤 워크)는 그대로 둔다.

## 결정 4. 유전체 레이아웃

| 옵션 | 설명 | trade-off |
|---|---|---|
| A. 설계대로 형질 24칸 고정 + 뇌 24–127 | 쓰지 않는 형질 칸(4개)을 예약 | 설계 문서와 인덱스가 같다. 예약 칸이 돌연변이로 흔들리지만 효과가 없다 |
| **B. 덧붙이기 유지** | 현재 17개 뒤에 형질 3개(포식 η, 이동 속도, 먹이 크기 비율 문턱)를 덧붙이고 뇌 104개를 덧붙인다. 합계 124 | 단계 2·3a 인덱스와 테스트가 그대로다. 부착 등 단계 6 형질은 뇌 뒤에 덧붙인다 |

**추천: B.**

## 결정 5. 성능

- 예상 추가 비용: 개체당 뇌 약 150 FLOP, 유전체 읽기 124 × 4B. 13만 개체에서 tick당 약 65MB 읽기로, 0.2 ms 수준이다(**추정**).
- 측정: S2(5만 마리 고정)와 13만 마리 포화 상태를 모두 잰다.

## 통과 기준 (단계 3b)

| 기준 | 내용 |
|---|---|
| 포식 수지 | 단위 테스트: 한 입의 몸 이동이 ε·(1 − ε)으로 나뉘고 C·N·e 수지가 맞는다. 먹이 묶음 n이 비율대로 준다. 두 포식자가 한 먹이를 노려도 먹이 몸이 음수가 되지 않는다 |
| 뇌 | 단위 테스트: 가중치를 직접 넣으면 출력이 손 계산과 같다. 가중치 0이면 행동이 단계 3a와 같다 |
| 이동 비용 | 단위 테스트: 속도에 따른 에너지 차감 |
| 선택 | 유지비가 붙은 형질(포식 η, 광합성 η)과 이동 속도의 분포가 시간에 따라 이동한다. (1차 평가 후 수정: 뇌 가중치는 중립 유전자와 퍼짐이 비슷해 선택과 표류를 구분할 수 없으므로 기준에서 뺐다. 측정값은 결과 문서에 기록한다.) |
| 창발 관찰 | 포식 계통 출현 여부와 시점을 기록한다(통과 조건 아님, S5는 단계 6) |
| S6 · S4 · S2 | 유지. S4는 최소 개체 수와 세포 수를 함께 보고한다 |
