## 결정 1. S3 (24시간 무사고, 메모리 증가 < 5%) 측정 방법

| 옵션 | 설명 | trade-off |
|---|---|---|
| **A. 실행 중인 뷰어 그대로 + 감시 스크립트** | 기록·HTTP·종 판별이 모두 켜진 실제 사용 상태. `scripts/s3_monitor.py`가 10분마다 메모리·tick·오차·기록 상태를 남긴다 | 사용자가 실제로 쓰는 경로를 검증한다. 시작 직후 메모리는 기준에서 뺀다(GPU·Taichi 초기화와 기록 큐가 차는 구간) |
| B. 기록 없는 헤드리스 실행 | `--headless` | 단순하지만 기록·HTTP 경로를 검증하지 못한다 |

**추천: A.** 메모리 기준점은 감시 시작 시점(가동 약 9시간, 2026-10-20 07:03)이다. 판정은 가동 24시간 이후 값과 비교한다.

## 결정 2. 태양 광도 증가

실제 태양은 시생대 이후 10억 년에 약 7%씩 밝아졌다. 압축 1 tick = 1,000년이면 100만 tick이 10억 년이다.

| 옵션 | 설명 | trade-off |
|---|---|---|
| **A. 실제 비율** | `solar += 7e-8 / tick`(100만 tick에 +0.07). 상한 1.0(현재 태양) | 지질 시계와 일관된다. 100만 tick 동안 기후 효과는 약 +2.8°C(`b_solar` 40 × 0.07)로 작다 |
| B. 가속 | 100배 빠르게 | 효과가 잘 보이지만 압축 비율과 어긋난다 |
| C. 없음 | | 상위 설계와 다르다 |

**추천: A.** 스냅샷에 태양 광도가 이미 들어 있다(`clim`).

## 결정 3. 군체 (부착)

상위 설계: 부착력이 높으면 분열 후 결합을 유지하고 에너지를 공유한다.

| 옵션 | 설명 | trade-off |
|---|---|---|
| A. 결합 그래프 | 슬롯마다 결합 상대 `(slot, uid)`를 두고 위치를 함께 움직이며 에너지를 나눈다 | 일반적이지만 원자 경합과 끊어진 결합 처리가 복잡하다 |
| **B. 군체 = 의도된 묶음** | 부착 유전자 확률로 분열한 딸세포가 새 슬롯으로 떠나지 않고 묶음 안에 남는다(`ncell × 2`). 이런 묶음은 `colony` 표시를 단다. 군체는 한 몸처럼 움직이고 에너지를 공유한다(슈퍼개체와 같은 계산). 대신 포식자에게는 군체 전체 크기로 비교된다(먹히기 어렵다) | 단계 3a의 슈퍼개체 계산을 그대로 쓴다. 이득(포식 방어)과 비용(퍼지지 못함, 한 곳의 자원만 씀)이 각본 없이 맞선다 |
| C. 생략 | | 상위 설계 단계 6 항목이 빠진다 |

**추천: B.**
- 풀이 꽉 차서 생긴 묶음(계산상)과 부착으로 생긴 군체(생물학)를 `colony` 표시로 구분한다. 포식 방어는 군체에만 준다.
- 부착 유전자에도 유지비를 붙인다.
- 화면: 군체는 세포를 겹쳐 그린 덩어리로 보이고, 정보 창에 "군체 n세포"로 나온다.

**예상 리스크**
- 포식 방어가 너무 강하면 모두 군체가 된다. 게이트에서 부착 유전자 분포를 기록한다.

## 결정 4. S4' (100만 tick 3회 중 2회 존속)과 S5 판정

| 옵션 | 설명 | trade-off |
|---|---|---|
| **A. 기록 없는 헤드리스 3회** | `survival_run.py <seed> 1000000`. 1회 약 40분~1시간 | 빠르다. 기록·종은 뷰어 장기 실행(S3)에서 따로 확인한다 |
| B. 뷰어 3개 | | GPU를 나눠 써서 3배 느리다 |

**추천: A.** seed는 번성·결빙이 나온 3과 번성하지 않은 1, 6을 고른다. S5는 지금까지의 게이트 기록(광합성 번성 9~11/20, 포식 출현)으로 판정한다.
